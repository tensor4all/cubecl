## What is implemented, measured, and still failing

- **CubeCL interop:** `Client::with_server`, CUDA raw stream/resource FFI access, C32/C64 plane reductions and CUDA C++ lowering. A100 focused reductions, product, stream stability and panic tests plus relevant Clippy passed. CUDA **LLVM** C32 reduction fails verifier (`llvm.fadd cube.c32`); use the tested C++ compiler path, never claim LLVM support.
- **CubeCL WGPU:** waiting for a sealed, fixed `SubmissionIndex`; two Vulkan focused tests (empty submission, staged writes) passed. WGPU lib suite at four-core affinity with one test thread: 562 passed / 14 ignored. With four test threads it SIGSEGV; an unmodified upstream baseline hung in adapter detection at four threads. The parallel gate is **not** green, and the cause remains unresolved.
- **CubeK matmul:** C32 via four F32 GEMMs without mutating caller descriptors. Eight focused tests with current local CubeCL passed, including both unequal-rank batch broadcasts, padding, offsets, conjugation, and rejection cases; Clippy passed. Full lib suite: 88 passed / 1 failed; unchanged upstream reproduces `tiled::cmma::cmma_tiled_weight_names_the_stage_across_m` (`No tile size is available for the problem`). A later four-job full-suite attempt stalled in an existing GPU Auto test; its cause is unknown.
- **CubeK FFT:** interleaved C32 CFFT, padded F32 RFFT/IRFFT via upstream butterfly/four-step; 21 focused tests and Clippy passed with current local CubeCL. Full FFT lib gate fails in unchanged-upstream planar F64 `fft::rfft::rfft_light_f64`, independently reproduced on its baseline. Neither full CubeK gate can be called passing. Both CubeK branches compile as libraries with their upstream default CubeCL pin (`cargo check -j 4 --lib`), so the two CubeK proposals do **not** require the CubeCL proposals to merge first.
- **tenferro integration is incomplete:** `.worktrees/tenferro-upstream-verify` at `tensor4all/tenferro-rs` `origin/main` `33e190fa367461e1e34f3797ddf396e05d7fefff`, branch `test/upstream-cubecl-cubek`, has an **uncommitted, local-path-only `Cargo.toml` change** for verification. It is intentionally **not** a portable patch or push target; preserve it. CPU-only default `tenferro-gpu` check passed, and CubeK FFT compiled, but `--features cuda,webgpu` fails with **556 compile errors across 27 tenferro files** due to CubeCL 0.10→0.11 API changes (`ComputeClient`, `ArrayArg`, `Runtime`, old IR/`TensorBinding`). CUDA-only 540/19, WebGPU-only 446/10; these include macro cascades, not 556 separate bugs. GPU integration tests could not run. The conditional design documents public API migration candidates but **no source migration was implemented**.
- **Apple/Metal:** upstream CubeCL lacks the fork's `PrimaryMemoryMode::HostVisible`, `WgpuMappedReadGuard`, guarded `map_read`/`map_write`, and fresh shared-memory context setup. Linux Vulkan execution cannot establish Metal memory coherency. No macOS/Metal device was available; do not disable `AppleContext` or treat a compile-only shim as compatible.

The feature branches have undergone bounded independent pre/post reviews; an initial large review timed out and **does not count**.
