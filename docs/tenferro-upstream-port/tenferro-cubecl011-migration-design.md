# Conditional design: tenferro-gpu CubeCL 0.10 → 0.11 migration (not approved/implemented)

## Requirements and boundary

Goal: build and test current tenferro `origin/main` (`33e190fa3`) against the four separately committed CubeCL/CubeK upstream-port branches, **without restoring old CubeCL generic APIs, changing tensor semantics, or hiding failures**. Current tenferro verification branch `test/upstream-cubecl-cubek` changes only root Cargo dependencies to local worktrees and a CubeCL patch; `cargo check -j 16 -p tenferro-gpu --features cuda,webgpu` failed with 556 errors in 27 files (`/tmp/tenferro-upstream-gpu-check5.log`). CPU-only default check passed; CUDA-only 540 errors/19 files, WebGPU-only 446 errors/10 files. Four dominant error files account for 462 errors (kernel macro cascades included). No tenferro source migration has started. User now requires all subsequent builds/tests capped at four cores (`cargo -j 4`, at most four test threads).

## Observed old/new contracts to retain

- CUDA runtime `crates/tenferro-gpu/src/cubecl/runtime.rs`: old `ComputeClient<CubeclCudaRuntime>` and `cubecl::Runtime::client` disappear. CubeCL 0.11 `cubecl::client::Client` is nongeneric; `cubecl::Device::Cuda(device).client()` supplies a client. The public tenferro CUDA runtime identity, retained primary CUDA context, thread-context restore, raw stream ordering, pinned scalar and cuBLAS lifetimes must be preserved. Server access requires the explicit typed `with_server::<cubecl_cuda::CudaServer, _>` (or equivalent typed closure), keeping existing `None`/error handling. `Client::get_resource::<cubecl_cuda::CudaServer>(handle)` now explicitly chooses the server type: `Client` submits a blocking server command, and `CudaServer::get_resource` calls `streams.ensure_written` followed by `command(stream_id,[binding])` to resolve stream dependencies (`cubecl-runtime/src/client.rs:449–471`, `cubecl-cuda/src/compute/server.rs:1337–1352`). This establishes buffer-failure/dependency checks and enqueue ordering, not GPU synchronization; external work must use the same raw stream and preserve buffer lifetimes. Confirm the cached stream-slot mapping still selects that same stream and launch requests are processed FIFO before claiming FFI ordering. CubeCL's newly ported `Client::with_server<S>` and `CudaServer::raw_stream(StreamId)` are the intended FFI seams; `StreamId` now lives in `cubecl_environment::stream`, not `cubecl::stream_id`.
- Dispatch `crates/tenferro-gpu/src/cubecl/dispatch.rs`: old `TensorBinding<CubeclCudaRuntime>` and `ArrayArg<CubeclCudaRuntime>` become nongeneric metadata `TensorBinding` and raw `BufferArg` for 1D physical scalar slices, with `BufferBinding` from `Handle::binding()`. Preserve prepared read/write authority, physical span/offset checks (`size()` is allocation length, `size_in_used()` subtracts offsets), backend identity and `invalidate_device_addr()` *before preparing mutable access*. Inspect `BufferArg` unsafe constructor alignment, zero-length, usable byte range and actual typed length; do not assume every caller uses physical indexing. Do not silently reinterpret a short/offset buffer or drop same-stream ordering; verify constructor safety preconditions against real CubeCL 0.11 sources. Use existing typed access helpers; no duplicated ABI layer or compatibility shim.
- Kernel frontend `kernels/elementwise.rs`, `structural.rs`, `indexing.rs`, `reduce/*`: host-launch `Array<T>` no longer implements `LaunchArg` (many E0277 cascades). Migrate launch entries that index flat physical buffers to CubeCL 0.11 `&[T]` / `&mut [T]` with `BufferArg`, and strided logical tensors to existing `&Tensor<T>`/`TensorBinding` when shape/stride metadata is required. Map removed shared-memory/IR operations to current `Shared::new_slice`, supported `Numeric`/ComplexCore operators by following current upstream CubeK/CubeCL examples, not textual replacement of every error. Preserve dtype semantics (F32/F64/C32/C64, bool), padding, offsets, zero-sized tensors, and numerical corner cases.
- Fusion `cubecl/fusion/{codegen,launch}.rs` uses removed `cubecl::ir::{Instruction,ManagedVariable,...}` and old `KernelBuilder::input_array`. This is a separate architecture change. A concrete *public* migration seam exists: current `KernelBuilder::buffer(TypeHandle)` and `KernelBuilder::build()` with settings at construction; public Pliron-backed CubeCL IR operations include builtin reads, buffer length, indexed load/store, comparisons, math, and `IfOp` (`cubecl-core/src/compute/builder.rs`, `cubecl-ir/src/dialect/{general,memory,branch,math}.rs`). Retain the existing `ElementwiseFusionPlan` value table and emit current `Value`/dialect operations, not a new fusion planner/compiler. Old `KernelLauncher::register_array` becomes `register_buffer(BufferArg, elem_size)` and explicit `declare_io` read/write roles, preserving parameter order, bounds guard, kernel cache identity (plan/type/cube/address), and NaN/signed-zero/complex semantics. **Do not** leave dead/uncompiled fusion, stub it out, or silently disable fusion. Public API existence is not compilation/exec proof.
- WebGPU `webgpu/runtime.rs`, `interop.rs`, `apple.rs`: migrate nongeneric `Client`/Device runtime and WGPU completion wait without changing domain isolation. Use explicit `cubecl::Device::Wgpu(selector).client()` for nongeneric WebGPU clients (never `Device::default()` because CUDA may win); use typed `with_server::<WgpuServer<AutoCompiler>, _>` for fixed submission completion and preserve retirement fallback. The ported CubeCL `WgpuSubmission` solves fixed completion, but upstream lacks fork `PrimaryMemoryMode::HostVisible`, `init_device_for_graphics_api`, `WgpuMappedReadGuard`, guarded `map_read`/`map_write`, and public shared storage access used by `AppleContext`/`webgpu/mod.rs`. Vulkan's crate-private mapped upload pointer does **not** provide Apple CPU read/write ownership or coherent Metal memory. Apple contexts must acquire fresh WGPU setup and unique registration so separate allocation-domain IDs do not alias one cached client. A separate upstream Metal memory ownership/mapping contract and real macOS/Metal tests are required. Do not remove Apple APIs, always-error shim, or claim Linux compilation validates shared Metal memory.

## Bounded implementation sequence *only if user confirms full migration scope*

1. Map old/new **CUDA** runtime and binding/stream ownership with a small CUDA compile probe; migrate central runtime and dispatch first, preserving domain and FFI safety. Use the typed server closure directly, import `cubecl_environment::stream::StreamId` through a direct optional dependency enabled by CUDA (only if no correct existing export suffices), and consume `Handle::binding()` as owned `BufferBinding`. Focused contract checks for stream slot identity, resource-resolution ordering/raw pointer lifetime, length/alignment/offset and mutable address invalidation; independent pre/post review for this public/safety boundary. Leave WebGPU for its own slice after CUDA correctness is established.
2. Migrate one representative flat elementwise kernel and one metadata-aware strided kernel, verify A100 CUDA C++ and available Vulkan, then apply the established pattern to the remaining call sites. Preserve Complex C32/C64 semantics; do not add one-off shim layers.
3. After scope authorization, build one isolated **F32 fusion probe** using the public 0.11 IR seam: two inputs, add then negate, two outputs, existing bounds guard and plan/type/cube/address cache identity. Validate definition construction, compilation and CUDA numerical output. Port the existing DAG emitter and launch binding roles only after this probe; then validate C32/C64 supported operations, clamp/extrema NaN/signed-zero cases, and cache/order behavior. Independent review covers the IR safety boundary. If a specific operation/lowering proves unsupported, report that concrete blocker rather than deleting fusion or inventing a shim.
4. Migrate ordinary WebGPU client/selector and typed completion independently, then port Apple host-visible WGPU **only after** a safe upstream Metal memory ownership/mapping contract and real Metal hardware/CI are agreed. Preserve fresh context/client identity, guarded read/write exclusion, CPU FFT/Cholesky paired access, GPU↔CPU visibility, cross-context rejection, and transfer counters; gate any PR claiming Apple support on real macOS tests. Linux `webgpu` compilation and Vulkan numerical/completion tests are necessary but insufficient.
5. Replace local path patches with merged upstream SHAs in tenferro after each corresponding CubeCL/CubeK PR is available. Run `cargo check -j 4 -p tenferro-gpu --features cuda,webgpu`, focused CUDA/WebGPU/FFT tests at ≤4 test threads, applicable repo-local gate, independent final diff review. Document known upstream CubeK planar F64 RFFT baseline failure and concurrent WGPU gate instability; never count them as passes. Do not push/open PR without user approval.

## Decision & acceptance

This is **read-only conditional design**, not authorization. User decision is still needed whether migrating 27 GPU files to CubeCL 0.11 is in this task rather than treating the four upstream PR candidates as a separately reviewable deliverable; and whether Apple host-visible memory is in scope with an available Metal device. Until then no broad tenferro source edits. Acceptance for a full migration is preserved public backend/ownership semantics, both GPU features compiling against upstream branches without fork shims, representative numerical/stream/FFT tests passing on actual devices, and honest local CI results. CPU-only check passing is insufficient.
